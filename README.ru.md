# Pi Code для VS Code

**Language / Язык:** [English](README.md) | Русский

Клиент VS Code для [Pi coding agent](https://github.com/earendil-works/pi-coding-agent). Общается с `pi --mode rpc` через stdin/stdout и даёт боковую панель с тем, что ожидаешь от агента в IDE: потоковые ответы с markdown, сворачиваемое мышление, вызовы инструментов с диффами, контекст из редактора, сессии, очередь сообщений и учёт стоимости.

Нужен pi ≥ 0.84 (протокол RPC с `agent_settled`, `get_entries` и под-протоколом extension UI).

## Возможности

**Чат**
- Потоковые ответы с markdown (заголовки, списки, таблицы, блоки кода с кнопкой копирования, ссылки).
- Блоки кода подсвечиваются цветами темы; правки файлов показываются построчным диффом со свёрнутым контекстом и счётчиком `+n -m`.
- Блоки мышления показываются свёрнутыми, если модель их отдаёт (`piCode.showThinking`).
- Селекторы модели и уровня мышления берут список из конфига pi; смена применяется к текущей сессии.
- Ошибки модели (401, 403, перегрузка) видны прямо на сообщении, при временных ошибках показывается прогресс авто-повтора pi.

**Инструменты**
- Каждый вызов инструмента — сворачиваемая карточка: `bash` показывает команду и потоковый вывод, `edit` — красно-зелёный дифф правки, `write` — содержимое файла, `read` — путь.
- Пути в карточках открывают файл; у `edit`/`write` и в полосе «Changed files» есть дифф рабочей копии против git HEAD.
- Запросы extension UI от pi (`select`, `confirm`, `input`, `editor`, `notify`, `setStatus`, `setWidget`) отображаются через quick pick, модальные диалоги, поля ввода, уведомления, строку состояния и виджет над полем ввода.

**Контекст из редактора**
- `Pi Code: Add Selection to Pi Chat` (Cmd/Ctrl+Alt+L, контекстное меню редактора) прикладывает выделение с путём и номерами строк; без выделения прикладывается весь файл.
- `@` в поле ввода открывает выбор файла из рабочей области; набранное руками `@относительный/путь` тоже подставляется (лимит `piCode.contextFileMaxKb`, файлы больше передаются путём для инструмента `read`).
- `Add File to Pi Chat` в контекстном меню проводника.
- Картинки: приложить, вставить из буфера или перетащить в поле ввода.
- Стрелка вверх в пустом поле листает уже отправленные запросы этой задачи, вниз — обратно; ненаправленный текст остаётся при своей задаче при переключении вкладок.

**Управление во время работы pi**
- Enter во время работы агента отправляет *steer*-сообщение (доставляется после текущих вызовов инструментов); кнопка *Queue* ставит сообщение в очередь до завершения.
- *Stop* (или Esc в поле ввода) очищает очередь, прерывает выполнение и возвращает текст из очереди в поле ввода.
- `!команда` выполняет команду оболочки через pi и кладёт вывод в контекст следующего запроса.
- `/` показывает команды расширений pi, шаблоны промптов и скиллы.

**Сессии**
- Несколько задач вкладками, у каждой свой процесс pi и файл сессии.
- Задачи восстанавливаются при повторном открытии рабочей области; история перечитывается из сессии pi, состояние webview не хранится.
- `Resume Session…` показывает сессии pi этой рабочей области (имя, первый запрос, число сообщений, дата изменения).
- Переименование (задаёт и имя сессии в pi), новая сессия в той же задаче, компакция контекста, экспорт в HTML, копирование пути сессии, перезапуск процесса pi.
- В футере после каждого прогона: сессия, модель, уровень мышления, заполнение контекста, токены и стоимость.
- Ctrl/Cmd+F ищет по переписке прямо в чате, Enter и Shift+Enter переходят между совпадениями, Esc закрывает панель.
- `Copy Last Answer` кладёт последний ответ в буфер обмена в том виде, в каком его отдаёт сам pi; `Show Logs` открывает канал вывода Pi Code.
- Кнопка «↓ Latest» появляется, когда прокрутка ушла от конца, пока pi пишет; у готовых ответов есть кнопка копирования; заполнение контекста в футере рисуется полоской.
- `Session Timeline…` показывает сессию так, как её пишет pi (запросы, ответы, смены модели и уровня мышления, компакции), и откатывает к любому запросу.
- `Next Model` / `Next Thinking Level` переключают модель и уровень мышления по кольцам самого pi.
- Упавший сам по себе pi поднимается снова на том же файле сессии, до трёх раз подряд (`piCode.autoRestart`).

## Откат и контекст редактора

**Откат.** У каждой твоей реплики при наведении есть кнопка отката к состоянию до неё, то же самое даёт
команда `Pi Code: Rewind Conversation`. Команды undo у pi нет: сессия — дерево записей, поэтому используется
`fork`, который переносит лист к родителю этой реплики, а её текст возвращается в поле ввода для правки.
Файлы, которые pi уже записал, при этом не откатываются — двигается только переписка.

**Контекст редактора.** Как и расширение Claude, Pi Code сам сообщает агенту, на что ты смотришь, без ручного
прикладывания: активный файл и строка курсора, выделенный текст, если есть выделение (`piCode.autoContext`),
и ошибки с предупреждениями, которые VS Code показывает для этого файла (`piCode.shareDiagnostics`).
Файл, приложенный руками, повторно не подмешивается.

**Вкладка редактора и строка состояния.** `Pi Code: Open Chat in Editor Tab` открывает тот же чат широкой
колонкой рядом с кодом; боковая панель и вкладка синхронны, вести задачу можно из любой. В строке состояния
видно, простаивает pi, работает или упал, там же накопленная стоимость, а в подсказке модель, усилие и
заполнение контекста; клик переводит фокус в чат.

**Режимы.** `Pi Code: Modes` переключает четыре тумблера сессии pi: авто-сжатие, авто-повтор и то, доставляются
ли управляющие и отложенные сообщения по одному или все сразу. Расширение проставляет настройки каждой
запускаемой сессии, поэтому сессия из панели ведёт себя как pi в терминале. pi хранит их глобально, так что
изменение видно и в CLI.

**Ветвление.** Откат не выбрасывает прежнюю линию работы: `fork` в pi продолжает в новом файле сессии,
поэтому покинутая ветка остаётся отдельной строкой в панели сессий, её можно открыть заново. Команда
`Pi Code: Branch Session` делает то же самое в текущей точке, ничего не отбрасывая, — удобно, когда хочется
попробовать второй подход, сохранив первый.

**Когда pi закончил вне поля зрения.** Задача, завершившаяся при скрытом чате, вешает счётчик на иконку
Pi Code, а `piCode.notifyWhenDone: notification` добавляет уведомление с первой строкой ответа и кнопкой,
открывающей задачу. Открытие чата счётчик снимает.

**Передача в терминал.** `Pi Code: Continue Session in Terminal` открывает pi в терминале на том же файле
сессии; свой pi для этой задачи расширение сначала останавливает — два процесса, пишущих один файл сессии,
подрались бы. Перезапуск задачи забирает сессию обратно.

**Перетаскивание.** Файлы и папки из проводника кладутся прямо в поле ввода: папка становится упоминанием,
картинка — вложением, остальное — контекстной плашкой.

## Сессии и режим размышления

**Панель сессий.** В контейнере Pi Code появилась вторая панель со списком всех сессий pi этой рабочей
области, сгруппированных по свежести (сегодня, вчера, на этой неделе, в этом месяце, раньше). В строке имя
сессии или её первый запрос, возраст, число сообщений и модель последнего запуска; открытые помечены, у
работающей крутится индикатор. Клик открывает сессию задачей или переключает на задачу, где она уже открыта.
В заголовке панели поиск, переключатель «эта область / все», показ архива и обновление; в меню строки
переименование, архивирование, копирование идентификатора, показ файла и удаление. Архив и локальные имена
хранит расширение, файлы сессий pi оно не переписывает; переименование открытой сессии дополнительно шлёт
`set_session_name`, чтобы имя попало в файл. Список сам обновляется, когда pi дописывает сессию.

**Режим размышления.** Когда шлюз задаёт усилие суффиксом в имени модели (`gpt-6-astra-xhigh-fast`),
родной селектор pi бесполезен: усилие там не параметр запроса. Pi Code разбирает имена на семейство, усилие
и скорость и даёт три органа управления: выбор семейства, лесенку усилия из реально существующих вариантов
и переключатель `fast`. При смене семейства усилие сохраняется, а если у нового семейства лесенка короче,
берётся ближайшее меньшее, о чём пишется в переписке. `Cmd/Ctrl+Alt+E` двигает усилие на ступень.
Если провайдер поддерживает настоящие уровни размышления, показывается родной селектор и шлётся
`set_thinking_level`.

## Установка

Сборка из исходников (нужны Node ≥ 18 и CLI `code`):

```bash
npm install
npm run install-local     # компиляция, упаковка, установка в VS Code
```

Затем `Developer: Reload Window`. Иконка Pi Code появится в панели действий.

## Настройки

| Настройка | По умолчанию | Смысл |
|---|---|---|
| `piCode.piCommand` | `""` | Путь к `pi`. Пусто — поиск в PATH плюс `/usr/local/bin`, `/opt/homebrew/bin` и установки nvm, поэтому обёртка в `/usr/local/bin` находится даже при пустом PATH у extension host. |
| `piCode.defaultModel` | `""` | Передаётся как `--model` новым задачам, например `litellm/gpt-6-astra-max`. Пусто — `defaultModel` из настроек pi. |
| `piCode.defaultThinkingLevel` | `""` | Применяется к новым сессиям, если модель заявляет поддержку reasoning. |
| `piCode.extraArgs` | `[]` | Дополнительные аргументы `pi --mode rpc`. |
| `piCode.sendOnEnter` | `true` | Enter отправляет, Shift+Enter — новая строка. Выкл: отправка по Ctrl/Cmd+Enter. |
| `piCode.restoreTasks` | `true` | Восстанавливать задачи и их сессии для рабочей области. |
| `piCode.contextFileMaxKb` | `96` | Лимит размера файла для вставки через `@упоминание` / Add File. |
| `piCode.showThinking` | `true` | Показывать блоки мышления. |
| `piCode.defaultEffort` | `""` | Усилие для новых задач, когда шлюз кодирует его в имени модели. |
| `piCode.preferFastVariants` | `false` | Предпочитать вариант `-fast` при смене семейства или усилия. |
| `piCode.autoContext` | `"selection"` | Что активный редактор добавляет к каждому запросу: `off`, `file` (путь и строка) или `selection` (плюс выделенный текст). |
| `piCode.shareDiagnostics` | `true` | Отправлять ошибки и предупреждения, которые VS Code показывает для активного файла. |
| `piCode.notifyWhenDone` | `badge` | Что делать, когда pi закончил, а чат не виден: `off`, `badge`, `notification`. |
| `piCode.autoRestart` | `true` | Поднимать pi заново, если он завершился сам (до трёх раз подряд). |
| `piCode.statusBar` | `true` | Держать сводку Pi Code в строке состояния (состояние, стоимость, модель и контекст в подсказке). |
| `piCode.autoCompaction` | `true` | Разрешить pi самому сжимать разговор, когда контекст заполняется. |
| `piCode.autoRetry` | `true` | Разрешить pi повторять запрос, упавший на стороне провайдера. |
| `piCode.steeringMode` | `one-at-a-time` | Как доставлять управляющие сообщения, отправленные во время работы pi. |
| `piCode.followUpMode` | `one-at-a-time` | Как доставлять отложенные сообщения, когда pi останавливается. |

Если провайдер не сообщает уровней размышления, родной селектор скрывается, а управление берут на себя выбор семейства и лесенка усилия; см. раздел выше.

## Разработка

```bash
npm run compile          # tsc
npm run check            # tsc + разбор имён моделей + рендер панели + контекст редактора, всё на стабах
node scripts/sessions-check.js  # список сессий на настоящем ~/.pi (только чтение)
npm test                 # скачивает VS Code и гоняет расширение в настоящем extension host
npm run smoke            # сквозной прогон через настоящий `pi --mode rpc` (один небольшой вызов модели)
npm run package          # сборка .vsix
```

Структура: `src/pi-process.ts` (подпроцесс, JSONL-фрейминг, сопоставление запрос/ответ), `src/conversation.ts` (чистый редьюсер из событий RPC в сообщения UI, восстанавливает историю из `get_messages`), `src/sessions.ts` (поиск файлов сессий), `src/webview.ts` (HTML/CSS/JS панели со своим рендером markdown), `src/extension.ts` (связка с VS Code: задачи, команды, контекст редактора, мост extension UI, диффы).
